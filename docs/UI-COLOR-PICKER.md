### 1.3 DOM 结构（当前实现，改样式前必须知道）

```
.picker-wrap                    ← 宿主（由 index.ts 持久化持有，**不要改成每次重建**）
└── .cp                         ← 取色器根；配色变量与尺寸预算都定义在这里
    ├── .cp-tabs                ← 圆角容器，内含 2 个 .cp-tab（RGB / HSV；.active = 当前）
    ├── .cp-wheel-row           ← flex 行：色轮 + 明度条（宽度合计 = 内容宽 176）
    │   ├── .cp-wheel-wrap      ← 156×156
    │   │   ├── <canvas.cp-wheel>   ← 色轮，canvas 绘制
    │   │   └── .cp-cursor          ← 游标（绝对定位，transform 定位）
    │   └── .cp-bar-wrap        ← 明度条容器 14×156
    │       ├── <canvas.cp-bar>
    │       └── .cp-vknob           ← 明度滑块（top 百分比）
    ├── .cp-fields              ← 数值行组
    │   ├── .cp-row × 3         ← 红/绿/蓝（RGB 段）或 色相/饱和度/明度（HSV 段），data-row=R/G/B/H/S/V
    │   │   ├── .cp-row-track   ← **滑条轨道**：flex:1，拖动命中区（ew-resize），填充层的裁剪容器
    │   │   │   ├── .cp-row-fill   ← 绝对定位填充层，宽度 = 数值比例（写在轨道里，不是整行）
    │   │   │   └── .cp-row-label  ← 叠在填充层之上（pointer-events:none，让 target 就是轨道）
    │   │   └── input.cp-num    ← 宽 42px、右对齐、无边框，**在轨道之外**（输入碰不到滑条）
    │   └── .cp-row.cp-alpha    ← **透明度行**（同结构；**类名保持 .cp-alpha，自动化断言依赖它**，
    │       │                       内部键名是 `Opacity`——值 1.000 = 全透明，0.000 = 不透明）
    │       └── 轨道底色为棋盘格（表示"未填充 = 透明"）
    │           ⚠️ 这一行与色板里的「透明」块**可以整行隐藏**（`showAlpha: false`），
    │           给"只接受实色"的颜色用（合成底色 matteColor 是 6 位 hex、没有 alpha）。
    │           切换靠 `display`，**不要改成"按需创建/销毁"**——那会在 update 时重建 DOM，
    │           正是 §2 第 4 条禁止的事。见 `paintFields()` 末尾的 `alphaRow.style.display`。
    ├── .cp-hexrow              ← 常驻：.cp-hex-label + input.cp-num + .cp-icon-btn（吸管）
    ├── .cp-swatches            ← 色板（本工具特有；参考图没有）
    │   └── .cp-swatch-row
    └── .cp-foot                ← 「收起」按钮（本工具特有）
```

**谁会用这个组件（两个实例，同一套代码）**：

| 实例 | 宿主 | 目标 | 说明 |
|---|---|---|---|
| 左侧取色器 | 左列色板面板里的 `.picker-wrap`（模块级持久宿主） | `primary` / `bg`（同一个实例，靠 `update({target})` 切换） | `index.ts` 的 `openPicker()`；入口就在左列，所以不需要额外滚动 |
| 合成底色取色器 | **参数面板里的 `.picker-wrap.inline`**，紧贴「合成底色」字段下方 | `matte`，并传 `showAlpha: false` | 就地展开/收起；展开时 `scrollIntoView({block:'nearest'})` 滚进视野 |

两边的回调由 `pickerCallbacks(getTarget)` 生成，**目标由参数传入**而不是共享一个模块变量——
两个实例可能同时开着，共享变量会把颜色写错路。

> **踩过的坑（值得记住）**：第一版让合成底色复用左侧那个取色器。功能是通的（合成 `.click()` 的
> 断言也绿），但用户反馈"点击没反应"——因为合成底色在右侧面板，取色盘却在左边出现，
> 视线在右边根本注意不到。**"点得动"不等于"看得见结果"**：入口在哪，面板就该在哪展开。

`index.ts` 的 `currentPickerValue()` 是"左侧实例当前该显示哪个值"的唯一出处。

### 1.4 关键尺寸与常量（`colorpicker.ts`）

| 常量 | 值 | 作用 |
|---|---|---|
| `WHEEL_SIZE` | 156 | 色轮 canvas 边长。**预算：156 + `WHEEL_GAP` 6 + `BAR_W` 14 = 176 = `.cp` 内容宽**，正好填满 |
| `BAR_W` / `BAR_H` | 14 / `WHEEL_SIZE` | 明度条尺寸；`BAR_H` 跟随 `WHEEL_SIZE` |
| `WHEEL_GAP` | 6 | 色轮与明度条的间隙（同时写进 `.cp-wheel-row` 的行内 style） |
| `CURSOR_R` | 6.5 | 游标半径（直径 13px），`positionCursor()` 用它把游标居中到指针处 |
| **`HUE_OFFSET`** | **−90** | **色相起点偏移**：屏幕角 `atan2(dy,dx)` 的 0° 在正右，参考图的 0° 在正下 → 减 90°。三处换算都走 `angleToHue()` / `hueToAngle()`，改回"0° 在正右"只需把常量改成 0 |
| **`ALPHA_MID`** | **0.5** | 透明度滑条的**分界**：左半边 = 全透明（1.000）、右半边 = 实色（0.000）。与输入框用同一条分界，避免两套阈值 |
| `ROW_SPECS` | — | 6 行的 key/标签/所属模型（红绿蓝 / 色相饱和度明度） |
| `showAlpha` | 状态（非常量） | 由 `ColorPickerState.showAlpha` 传入，默认 true。false 时藏掉透明度行与「透明」色块——给合成底色这类"只接受实色"的颜色用。**用 display 切换，不重建 DOM** |
| `norm3` | — | 数值显示格式：归一化 3 位小数（参考图 `0.800`） |

改尺寸时**必须同时**改：`colorpicker.ts` 常量、`style.css` 里对应的硬编码（若有）、
`positionCursor()` 的游标半径偏移，以及 `tool/e2e-picker.mjs` 里 `wheelSize === 156` 与"不溢出"两条断言。

## 2. 动手前必须知道的 8 条"碰了就坏"约束

这些不是风格建议，是踩过的真实缺陷（详见 `docs/ARCHITECTURE.md` §8.3）：

1. **宿主元素 `.picker-wrap` 必须跨渲染存活。**
   它由 `index.ts` 的 `pickerHost`（模块级变量）持有。如果你让 `renderPickerPanel()` 每次新建宿主，
   取色器会"打开正常、一拖动就消失"（拖动会触发一次重渲染，实例 DOM 被留在旧宿主上）。

2. **所有"指针坐标 → 几何比例"的换算都要判零尺寸。**
   `getBoundingClientRect()` 在元素不可见时全是 0，除零会产生 `NaN`，
   并沿色相/饱和度一路污染成 `#NaNNaNNaN` 写进主色。参考实现见 `wheelFromEvent()`。

3. **`setPointerCapture` 必须走 `safeCapture()`。**
   它对"非活跃 pointerId"抛 `NotFoundError`（合成事件、部分触控设备），而它位于处理器开头，
   一抛就整段取色逻辑不执行。直接用 `el.setPointerCapture(pointerId)` 会重新引入这个 bug。

4. **拖动过程中不要重建 DOM。**
   `refresh()` 只更新数值文本、游标 transform、填充宽度与渐变；`repaint()` 才重建色板。
   拖动时调 `repaint()` 会让 pointer capture 与焦点失效（视觉上表现为"拖着手感发飘/断掉"）。

5. **`window.addEventListener('pointerup' / 'pointercancel' / 'blur')` 的兜底不能删。**
   它保证"拖到窗口外松手"不会让拖拽状态悬挂。新增的全局监听都必须在 `dispose()` 里成对移除。

6. **数值行 = `[滑条轨道][数值框]`，拖动几何基准是轨道（`.cp-row-track`），不是整行。**
   两个原因：① 填充画在轨道里，"点在轨道的哪里"必须等于"填充画到哪里"，否则轨道右端永远拖不到 1.0；
   ② 数值框必须在轨道**之外**——参考图里数字是压在滑条上的，但那样"点数字框"与"拖滑条"共用一个
   命中区，输入时必然误触（实测：点 Alpha 的数字框会把它从透明翻成实色）。
   这不是靠事件拦截（`stopPropagation` / 阈值判断）实现的，而是靠**结构上不重叠**，拦截总有漏网。
   > 2026-09-13 用户明确要求"把数字改到滑条右边"后落地；这是**有意偏离参考图**的一处（见 §6）。
   > 代价：滑条只占行宽的约 3/4，填充看起来比参考图短。
   > 若将来想回到参考图那种"数字压在滑条上"的外观，只需把 `.cp-row` 的 `background` 改成
   > `var(--cp-slot)` 并把输入框宽度调回 66px —— 但**不要**把指针事件挪回整行。

7. **提交时机不能改。**
   拖动中只 `onPreview()`（实时预览，不进撤销栈）；松手 / 数值输入 / 点色块才 `onCommit()`。
   若改成拖动中提交，一次拖动会产生几十条撤销记录。

8. **取色器内的 `input` 必须盖掉全局输入样式。**
   `style.css` 里有一条 `select, input[type="number"], input[type="text"], .hex-input, .num {…}`，
   特异性 (0,1,1) 高于单个类 (0,1,0)。取色器的数值框因此写成 `.cp-row .cp-num` / `.cp-hexrow .cp-num`，
   否则行内数字会重新长出深色圆角框、盖住滑条填充。

## 3. 常见改造任务该改哪里

### 3.1 换配色（最高频）

只改 `style.css` 的取色器段落。**不要**在 `colorpicker.ts` 里写颜色字面量。

取色器内部允许比全站更贴近参考图，做法是**只在 `.cp` 作用域内覆盖变量**（不外溢到界面其它区域）：

```css
.cp {
  --cp-bg: #181818;      /* 面板底 + 行间分隔线 */
  --cp-slot: #545454;    /* 滑条未填充槽 / 未激活标签 */
  --cp-fill: #4772b3;    /* 滑条填充 / 激活标签 */
  --cp-field: #1d1d1d;   /* Hex 输入框底 */
  --line: #545454;       /* 覆盖全站变量，仅在本作用域生效 */
  --text: #e6e6e6;
  --dim: #a7a7a7;
  background: var(--cp-bg);
}
```

全站变量本体在 `style.css` 的 `:root`（`--bg` / `--bg-2` / `--bg-3` / `--line` / `--text` / `--dim` / `--accent` / `--accent-2`）。
若任务要求"整体换成参考图配色"，那是**全站换肤**，需要单独确认（见 §6）。

### 3.2 改色轮外观（尺寸 / 起手角度 / 描边 / 游标样式）

- **尺寸**：改 `WHEEL_SIZE`，并保证 `WHEEL_SIZE + WHEEL_GAP + BAR_W = `.cp` 内容宽（176）`，
  否则色轮/明度条会溢出面板（旧版就溢出过 38px）。要更大的轮子必须先加宽全局左栏（`style.css` 的
  `.main` 那条 `grid-template-columns: 232px 1fr 300px`），那属于全站布局。
- **色相起点**：改 `HUE_OFFSET`。参考图是 `-90`（0° 在正下方）；`0` = 0° 在正右。
  改完必须同步改 `tool/e2e-picker.mjs` 里三条方位断言（下红 / 左绿 / 上青）。
- **圆边羽化**：`drawWheel()` 末尾的 1px 抗锯齿别删，否则圆边发锯齿。
- **游标**：样式在 `style.css` 的 `.cp-cursor`，定位由 `positionCursor()` 用 `transform` 写入。
  改游标尺寸时同步改 `CURSOR_R`（= 直径 / 2）。

### 3.3 改布局（例如"明度条改横条放色轮下方"）

改 `colorpicker.ts` 里 `wheelRow` 的组装方式即可，配套改 `.cp-wheel-row` 的 CSS，
并删掉 `.cp` 上的宽度预算注释。**不要在 DOM 结构里加"每次都重建"的中间层**（见约束 1）。

### 3.4 改数值行（标签 / 行数 / 显示格式）

- 行定义：`ROW_SPECS`（key / 标签 / 所属模型），标签目前是 红·绿·蓝 / 色相·饱和度·明度。
- 结构：`.cp-row` = `[.cp-row-track（含 .cp-row-fill + .cp-row-label）][input.cp-num]`；
  轨道是拖动命中区，数值框在轨道外（见约束 6）。新增行时在 `numRow()` 里同步
  `rowEls` / `rowTracks` / `rowFills` / `fieldInputs` 四张表，否则拖动或显隐会漏掉它。
- 显示与填充：`paintFields()`（数值文本 + `.cp-row-fill` 宽度）。
- 输入解析与拖动**共用** `setChannelRatio(key, 比例)`，避免"拖出来的值"和"输入的值"刻度不一致；
  `applyNumberField()` 只负责把输入换算成比例。显示是归一化 0–1（参考图 `0.800`），**输入兼容旧刻度**：
  `>1` 时按 0–255（RGB）/ 0–360（H）/ 0–100（S、V）解释，老习惯输入不会被当成 1.0。
- RGB 通道改值是**字节直改**（`hexToRgb(currentHex)` → 改一个字节 → 反推一次 HSV）。
  不要改回"经 HSV 往返"：HSV⇄RGB 各有取整，往返会让微调弹回原值（踩过）。
- 新增行：在 `ROW_SPECS` + `sliderKeys` 加一项；Alpha 与 Hex 是常驻行，不走 `ROW_SPECS`。
- **末行是两态透明度滑条**：数值口径是**透明度**（0.000 = 不透明，1.000 = 全透明），不是 alpha。
  `ALPHA_MID`（0.5）是唯一分界——拖动越过中线就翻状态，输入框也用同一条分界。
  拖动方向两侧都要**实时**反馈：向右恢复实色走 `onOpaque()`（清 transparent，不进撤销栈），
  向左变透明走 `onTransparent()`。只调 `onPreview()` 是不够的——它不清 transparent，
  填充会一直停在 0%、数字停在 0.000，拖起来"没反应、松手才跳"（踩过）。
  真要做**连续** alpha 属于数据模型改动（core 的 alphaMask + 各导出路径），不在 UI 范围内。
- **文字不可选中**：`.cp` 上写着 `user-select: none`——拖滑条时鼠标会扫过标签与数字，
  不挡的话浏览器会把沿途文字划进选区（`touch-action` 只挡触摸滚动，挡不住选词），观感很脏。
  取色器内的 `input` 单独写了 `user-select: text`，新增输入控件时别忘了这一条，否则框内没法拖选替换。

### 3.5 改色板（行数 / 每行几个 / 是否显示号色）

- 数据来源：`index.ts` 的 `pickerGroups()`——它返回 `{ name, colors }[]`，想加"拼豆号色"就改这里。
- 渲染：`paintSwatches()`。当前每行最多 32 个（`.slice(0, 32)`），行内换行由 CSS `flex-wrap` 决定。

## 5. 现有断言覆盖了什么（避免重复造轮子）

`tool/e2e-picker.mjs` 当前 17 项：

1. 结构：色轮存在且 `wheelSize === 156`、明度条、透明度行、RGB/HSV 两段、行标签 红/绿/蓝/透明度、Hex 行常驻、色板行数 ≥ 2
2. 布局：色轮 + 明度条**不溢出** `.cp` 内容盒（旧版溢出 38px 的回归守卫）
3. **色轮方位：正下方 = 红（色相 0°）**
4. **色轮方位：正左方 = 绿（色相 90°，顺时针递增）**
5. **色轮方位：正上方 = 青（色相 180°）**
6. 色轮圆心 → 灰阶（半径 = 饱和度）
7. 色轮边缘 → 通道极差明显（饱和度夹满，不甩出圆外）
8. 明度条：顶部比底部亮（V 轴方向）
9. 标签切换：RGB / HSV 两段改变数值行（…/透明度）；HSV 数值是 0–1 三位小数；Hex 行常驻
10. **数值行滑条：填充宽度 = 数值比例（`#FF6600` → R 100% / G 40% / B 0%），数值为 1.000/0.400/0.000**
11. Hex 数值输入生效
12. 色板点选生效
13. **透明度行整条都有响应**：左半边 = 全透明（数值 **1.000** / 填充 0%）、右半边 = 实色（数值 **0.000** / 填充 100%）；**中段（0.35 / 0.65）也必须翻转**，且松手前就即时翻转（拖动命中区 = `.cp-alpha .cp-row-track`）
14. **数值框在滑条右侧**：每一可见行的 `input.cp-num` 左沿 ≥ `.cp-row-track` 右沿（结构隔离的回归守卫）
15. **数值框不触发滑条**：在绿行/Alpha 行的数值框上按下并拖动，填充百分比与"透明/实色"状态都不变
16. **拖动滑条不会选中沿途文字**：用 CDP 真实鼠标事件按住扫过标签与数值框，`window.getSelection()` 必须为空，且拖动本身生效（合成 PointerEvent 测不出文字选区，必须用真实输入）
17. 取色不改变画布内容

## 6. 与参考图的**有意差异**（不要当成 bug 去"修"）

| 差异 | 参考图 | 本项目 | 为什么保留 |
|---|---|---|---|
| **末行标签与数值** | `Alpha`，1.000 = 不透明 | `透明度`，**1.000 = 全透明**、0.000 = 不透明 | 本工具这一行是"透明色"开关而不是连续通道，界面其它地方一律说"透明"（透明色 / 透明挖洞 / 色板「透明」块）。用 alpha 口径会出现"1.000 = 完全不透明"这种与直觉相反的读法。注意填充画的仍是"颜色有多少"（全透明 → 空条），与数字口径相反但同指一事 |
| **数值框位置** | 数字**压在滑条上**（右对齐在填充层之上） | 数值框在滑条**右侧之外**（轨道 + 6px 间隙 + 42px 输入框） | 参考图的布局让"点数字框"与"拖滑条"共用一个命中区，输入时必然误触（实测点 Alpha 数字框会把透明翻成实色）。结构隔离是唯一可靠的防误触方式；代价是滑条只占行宽约 3/4，填充看起来比参考图短 |
| 色板 + 透明块 + 「收起」 | 没有（Blender 浮窗） | 有 | 本工具的功能：常用色、透明挖洞、收起面板；删掉是功能倒退 |
| Hex 位数 | `#E7E7E7FF`（8 位含 alpha） | `#E7E7E7`（6 位） | `core/types.ts` 的 `normalizeHex` 只认 6 位（改它等于改算法层），且本工具的 alpha 是"透明色"开关、不是连续通道，多两位会假装有连续 alpha |
| 吸管图标 | 白色斜置滴管图形（**实心圆胶头 + 空心锥形管身 + 靠尖端一圈"箍"**） | **内联 SVG**（`src/app/ui/icons.ts` 的 `iconEl('eyedropper')`，与工具条「取色」同一个图标），三件套比例照 Blender 那颗按钮还原；`⌖` 仅作图标缺失时的兜底 | 不引入图标字体/外链资源，保持单文件、离线、运行期零依赖。这里返工过两次：先是 `⌖`（准星）"不像吸管"，改成 SVG 后**胶头画成空心**又依次读成"钩子 / 图钉 / 钢笔"——**必须把胶头填实**，实空对比才是"橡胶头 + 玻璃管"。改形状请重跑 `npm run e2e:pdf`（有几何断言守着），并把放大截图拿出来对照——用 `npm run shot:el -- ".tool-btn" icon 6`（`tool/shot-el.mjs`，产出到 `.tmp-shots/`） |
| 数值刻度 | 0.800（Blender 的 **线性** 值） | 0.906（同一颜色的 **sRGB** 值） | 本项目内部一律 sRGB（与 CSS/PNG/项目文件一致，见 `colorpicker.ts` 头部注释）。同一颜色 `#E7E7E7` 在两边**看起来完全一样**，只是数值刻度不同 |
| 面板/色轮绝对尺寸 | 面板 292 / 轮 238 | 面板 196 / 轮 156 | 参考图是独立浮窗；本项目取色器嵌在 232px 左栏里（内容宽 176）。**轮:面板 比例已对齐**（0.80 vs 0.815），要更大的轮子得加宽全局左栏 |
| Alpha 行 0.000 时的槽底 | 纯 `#545454` | 棋盘格 | 本工具的 alpha 是"透明色"开关：0.000 时用项目既有的棋盘格语言一眼看出"这是透明"。1.000 时全蓝，与参考图一致 |

## 7. 其他边界（不要自作主张）

| 事项 | 说明 |
|---|---|
| 是否只改取色器 | 用户明确要求的是"**调色界面**"。若要顺带改全站配色（顶栏/左栏/参数面板/状态栏）或左栏宽度，请先确认 |

## 8. 一句话交接

> 改 `src/app/ui/colorpicker.ts`（结构/绘制/交互/数值）与 `src/app/style.css` 的取色器段落；
> 配色只在 `.cp` 作用域内覆盖变量，不要在 TS 里写颜色字面量；

> 改完跑 `npm run verify`，并为本次改动补一条断言、再故意改坏确认能变红。
