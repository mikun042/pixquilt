## 2. 铁律

1. **改 `src/` 后必须 `npm run build`**。构建脚本会把 `dist/index.html` 复制到根目录 `像素画工作台.html`
   并**核对两者 SHA256 一致**——不一致直接失败。
2. **`npm run verify` 全绿才算完成**，不接受"我本地只跑了单测"。
3. **改了算子或参数必须 `npm run describe`** 重新生成 `docs/AGENT_API.md`。
   跑完再 `npm test`——`describe-freshness` 会把生成结果与仓库里的文件**逐字节比对**，
   漏跑或手改都会直接变红（见 §5）。
4. **`src/core/` 里不允许出现 `node:` 前缀**，也不允许出现 `document.` / `window.`
   （浏览器构建会失败，见 §6 第 1 条）。平台能力通过参数注入：`src/io/`（Node）与 `src/app/`（浏览器）。
5. **每项改动单独提交**，信息用 `feat:` / `fix:` / `refactor:` / `docs:` / `test:` 前缀。
6. **删东西之前先搜引用**：本项目有过"文档提到的方法根本不存在"的幽灵引用。
   `grep -r "要删的名字" src tool docs README.md` 之后再动手。

## 3. 验证链

```bash
npm run verify
```

它按顺序跑十件事，任一步失败即中断：

| 步骤 | 命令 | 内容 | 需要浏览器 |
|---|---|---|---|
| 类型检查 | `npm run typecheck` | `tsc --noEmit`，开着 `noUnusedLocals`——**未使用的变量会直接报错** | 否 |
| 单元测试 | `npm test` | 141 项（管线 / 13 类算子 / sanitize / 导出格式 / PDF 结构 / 图集元数据三引擎 / 常量表 / 撤销栈双上限 / 油漆桶连通规则 / **色板条目编辑与合并重映射** / **R1 分层** / **草稿** / **生成物新鲜度**） | 否 |

（`npm test` 只跑 `src/test/`，**不启浏览器**；`src/app` 里能单测的逻辑都尽量抽成了纯模块，例如 `history.ts`。）

| 端到端 | `npm run e2e` | 36 项（UI 装配 + 绘制 + 导出 + 导入 + 尺寸方式 + 预设编辑 + 合成底色取色盘 + 合成底色吸管去向 + 放大镜 + 显示勾选框重绘 + `?` 速查表 + 油漆桶 + 撤销栈记账 + 算子编辑跨路径同步 + 整体替换=新基线 + 页面算子可执行性） | **是** |
| 取色器专项 | `npm run e2e:picker` | 18 项（色轮几何方向、标签、色板、透明度） | **是** |

**为什么 `npm run bench` 不在验证链里**：`verify` 的契约是"任一步失败即中断"，
而基准的**绝对耗时随机器浮动**——把它接进来就等于让"CI 跑在慢机器上"变成假警报。
所以分工是：验证链只跑**与机器无关**的判定（含 `--selftest` 里那条"bench 存在且已接线"的守卫），
性能结论由 `npm run bench` 自己断言**比值**（缓存快几倍、pixbin 快几个数量级），需要时手动跑。

改 UI 外观与排查交互时的辅助工具：

```bash
npm run shoot                       # 整页截图 + 裁出取色器区域 → .tmp-shots/
npm run ref:analyze -- <png 路径>   # 参考图/截图结构分析（主色直方图、字符画、条带）
npm run shot:el -- <css选择器> [文件名] [放大倍数] [--click 文案] [--height 1200]
                                    # 单个元素放大截图（--click 可先点一下再截）
npm run probe -- "<js表达式>" [--pre "<js>"] [--click 选择器] [--wheel 选择器] [--move 选择器]
                                    # 在真实页面里跑 JS 并打印结果；可发**真实**鼠标事件
```

> `probe` 是排查"交互到底有没有发生"的主力：合成 `.click()` / `.dispatchEvent()` 绕过命中测试，
> 而它走 `Input.dispatchMouseEvent`，能验"点得动吗 + 看得见结果吗"（§3.2 第 3、5 条）。
> 两个工具都只读页面、不修改任何东西。

### 3.1 断言必须"能因真实缺陷而红"

这是本项目对测试的唯一价值判断，不是数量：

> 每写一条断言，都要能说出**什么样的真实缺陷会让它变红**。
> 做不到就说明它只是在复述实现。

提交前用**变异测试**自证：故意把被测行为改坏 → 断言变红 → 改回 → 变绿。
本项目的提交说明里会记录这一步（例如"让 `mirror` 抛『未知算子』→ 页面算子可执行性断言变红"）。

反面教材（真实发生过）：曾把 `describeOps().length` 断言写死成 `10`，改成 `12` 之后
它只是"再抄一遍"，页面真漏了算子照样绿。改成逐个真调一次页面宣称的算子才有意义。

### 3.2 测试容易踩的五个坑

不知道这五条，会得出**错误的结论**（把产品正常行为报成缺陷，或反过来把缺陷报成正常）：

1. **无头浏览器默认视口 800×600 会隐藏侧栏**。要测右侧栏必须先
   `Emulation.setDeviceMetricsOverride` 到 1400×900。
   （`tool/e2e.mjs` 一直没设视口，直到"合成底色色块"那条几何断言暴露出来：色块矩形是 `0×0`、
   命中测试落在页头。**要测哪一侧的面板，就先把视口摆成它存在的样子。**）
2. **隐藏元素的 `getBoundingClientRect()` 全为 0**，几何断言会"假通过"。
   断言尺寸时同时断言**非零**。
3. **合成 `.click()` 不经过命中测试**，测不出 `pointer-events`、遮挡、不可点击。
   涉及"点得动吗"的断言一律用 `Input.dispatchMouseEvent`。
4. **无头下 rAF 可能不产帧**。断言绘制结果前要**轮询**，不要立即读取。
   （也不要把 rAF 当作唯一的去重机制——见 §6 第 2 条。）
5. **"点得动"不等于"看得见结果"**。真实鼠标事件只证明事件落到了元素上，
   不证明用户点完之后看到了变化。合成底色那次两条都验了：功能通、命中测试也过，
   用户仍报"点击没反应"——因为合成底色在**右侧**参数面板，取色盘却出现在**左侧**列，
   视线在右边的人根本注意不到；而色块本来就在面板靠底部，插在它下面的面板还会落到视口外。
   **凡是"点了会发生什么"的断言，都要顺带断言那件事出现在视口里、且在用户视线所在的面板内。**

## 4. 结构规则（五条不可妥协）

| # | 规则 | 为什么 | 怎么被强制 |
|---|---|---|---|
| R1 | **依赖单向**：`core`（纯逻辑，零 DOM）← `io`/`app` ← `tool` | 旧项目 `core` 里混了 DOM 下载与 UI 色彩，导致"能不能单测"要靠人记 | **`src/test/core-layering.test.ts` 静态扫描**（`node:` / `document.` / `window.` / `globalThis.` / `localStorage` / `navigator`，命中即红）；外加浏览器构建会因 `node:` 失败 |
| R2 | **单一真源**：算子与参数的元数据只在 `src/core/spec.ts` 定义一次 | 旧项目同一份算子表在文档与代码各写一遍，已经漂移 | 单测断言 `spec 算子集 == ops.ts 实际处理集 == 算子总数`；e2e 断言页面宣称的每个算子都真能执行 |
| R3 | **纯函数优先**：新算法先写 `core` 纯函数 + 单测，UI 只做编排与提示 | 可回归、可基准比对 | review + 现有 `core/` 的写法示范 |
| R4 | **对外契约集中**：`window.pixelArtStudio` 只在 `src/app/automation.ts` 里组装 | 旧项目 API 内联了几十行业务逻辑，与 UI 重复 | 契约层有 e2e 直打（页面装配 + 算子可执行性） |
| R5 | **无隐式全局**：跨模块通信走显式 store 订阅 | 旧项目有两个自制事件总线，职责靠注释维持 | review |

> **R1 的静态检查已补上（2026-09-15）**：`src/test/core-layering.test.ts` 逐文件扫描 `core`，
> 命中 `node:` / `document.` / `window.` / `globalThis.` / `localStorage` / `navigator.` 即失败，
> 报错带文件、行号与那一行原文。**没有引入 ESLint**（运行期零依赖是硬约束，devDependency 也不轻率增加），
> 用一个 40 行的注释剥离器 + 正则在 `npm test` 里完成同一件事。
>
> 补它的理由不只是"原设计提过"：自然约束**只挡得住一半**——`node:` 会让浏览器构建失败，
> 但 `document.`/`window.` 在浏览器侧完全正常，只有 Node 直调（L3）或单测里才炸。
> 也就是说 **DOM 泄漏是静默的**，而 L3 正是"agent / CI 只要结果不要 UI"的主力入口。
> 两条防线（node: 与 DOM）都做过变异验证：故意把 `import 'node:zlib'` 与
> `document.createElement` 加进 `core/raster.ts`，断言各自变红并指出正确行号。

### 4.1 四层接入（同一个 `core`，四种用法）

分层不是为了好看，是为了**同一份实现服务所有入口**，避免"页内一套、CLI 一套"的双实现漂移：

| 层 | 入口 | 适用场景 |
|---|---|---|
| L1 页内 API | `window.pixelArtStudio` | AI 操作已打开的页面；Playwright / CDP `evaluate` |
| L2 批处理 CLI | `node tool/artc.mjs` | 整套素材批量出图，不需要浏览器 |
| L3 **Node 端直调 core** | `import { runPipeline } from 'src/core/pipeline.ts'` | agent / CI / 服务器只要结果，不想要 UI；`core` 是纯函数，无 DOM 依赖 |
| L4 自描述与预演 | `describe()` / `--describe` / `validateParams()` / `--dry-run` | agent 冷启动自查、改参前预演 |

**L3 是这套结构成立的关键**：`core` 不依赖 DOM，所以 Node 能直接 import；
平台能力（PNG 编解码、文件 IO、canvas）通过参数注入，分别落在
`src/io/`（Node）与 `src/app/`（浏览器）。这样一次批处理不必
"起浏览器 → CDP → 页面渲染 → dataURL 序列化 → 回传"绕一圈 base64。

新增功能时先问一句：**它能不能落在 `core`？** 能就落在那儿，四个入口自动都有。

### 4.3 代码约定

- **命名**：文件名与主导出名对应；纯函数动词开头；返回布尔的用 `is` / `has` / `can`。
- **注释只写"为什么"**：不复述代码在做什么。涉及算法取舍必须留注释并指向
  `docs/ARCHITECTURE.md` 的对应小节。
- **错误信息**：中文、面向使用者与 agent、**同一种错误只用一种措辞模式**。
  能给出"正确写法"的就给出来（例如未知参数报错会提示最接近的正确参数名）。
- **魔法数字**：全部集中在 `src/core/limits.ts`（2048 / 16384 / 256 / 50 帧 /
  `ALPHA_THRESHOLD=128` / `CLEANUP_MIN_SIZE`…），每个都有一句解释。

## 5. "防漂移"机器检查（现状：6 条真在跑，无未实现项）

**真实生效的**：

1. **元数据一致性**：`spec.ts` 的算子集 == `ops.ts` 的 `switch` 处理集 == 算子总数常量。
2. **产物同步**：构建后校验 `dist/index.html` 与根目录 `像素画工作台.html` 的 SHA256 一致。
3. **页面自描述可执行性**：e2e 逐个真调页面宣称的每个算子——`spec` 加了算子但
   `applyOps` 没接时会走进 `default` 分支报"未知算子"，从而变红。
4. **CLI 参数表对账**：`tool/describe.mjs` 生成 `AGENT_API.md` 时，会拿手写的参数表与
   `tool/artc.mjs` 的 `KNOWN_FLAGS` 对账，**少收录或多收录任何一个开关都直接抛错**。
   （2026-09-14 补上。此前这张表漏了 12 个已实现的开关而无人发现——因为"单一真源"只覆盖
   算子与参数元数据，不含 CLI 开关。）
5. **文档新鲜度**：`src/test/describe-freshness.test.ts` 把 `describe.mjs` 的 `build()` 输出与

## 6. 本项目踩过的坑（省下你一次返工）

这些都是**真实发生并有提交记录**的，不是假设：

1. **`core` 里 `import 'node:zlib'` 会让浏览器构建失败**。所以 PNG 编码被拆成
   `src/io/node-png.ts`（Node，注入 zlib）与 `src/app/canvas-png.ts`（浏览器），
   `core/png.ts` 只留纯编解码。
2. **无头下只靠 `requestAnimationFrame` 做重绘去重，会让画布永远空白**——
   rAF 不回调，去重标志位堵死后续所有重绘。修法是 **rAF + 定时器双保险**。
3. **字节布局要逐字段写清并加"结构断言"**。曾以为 `DataView.setUint32` 有 bug，
   实际是自己设计的 pixbin 头**字段重叠**（offset 6 的 uint32 占 6–9，又去写 offset 8）。
   只测"往返一致"抓不到字段互相覆盖。
4. **模拟测试数据要看几何是否可达**。曾断言"对称图形 `rotate180` 应产生改动"，
   而它本就不该变——**断言写错会伪装成产品缺陷**。
5. **PowerShell 的 `Set-Content` 会改行尾与编码**。用它改源码曾把 `+47/−1` 的 diff
   变成 `+1044/−489`。改源码请用编辑器式工具，别用 shell 重写文件。
6. **`execFileSync` 的子进程 stdout 在本机会漏到父进程**，拿不到捕获串。
   需要"读另一个模块的导出"时，**直接 import** 比 spawn 子进程可靠——
   前提是被导入的脚本有"直接执行守卫"（见 `tool/artc.mjs` 末尾）。
7. **把滚动容器从面板本体挪到内层容器时，忘了补 `min-height: 0`**，于是面板不再滚动、
   整个页面反而变长。`.rail` 原来自己带 `overflow-y: auto`（滚动容器同时也是 grid 子项），
   改成 `.rail-body` 负责滚动之后，`.rail` 的自动最小高度回到"内容高度"——面板撑得跟内容一样高，
   滚动条跑到页面上，用户看到的是"**面板里的滚动条滚不动**"。
   很好验：`scrollHeight` 与 `clientHeight` 相等就说明没有可滚区域
   （实测当时 `clientHeight` 是 1136，而视口只有 520）。
8. **`display: none` 会把 grid 项从布局流里摘掉**，剩下的项会被自动重排到前几列。
   隐藏三栏布局里的一栏时，只写 `display: none` 而不同时把 `grid-template-columns` 改成两列，
   结果是"**画布宽度变成 0**、另一栏却占满了整行"。两者必须一起改。
9. **生成物没有新鲜度断言就一定会漂移，而"被遮蔽的死数据"漂移了也看不见**。
   `icons.ts` 里那两张 path 表是生成物，长期只有"人工记得重跑"这一道防线，于是
   `PIXEL_PATHS.undo` / `.regenerate` 与形状定义漂移了——**而且不产生任何可见症状**，
   因为同名时渲染优先读 `SVG_PATHS`、这两条永远读不到。同一次排查还发现 SVG 那半边更严重
   （形状画在 32 设计网格、viewBox 是 24，缺缩放 → 8 个图标被裁掉大半，同样静默）。
   → 两个教训：① 生成物必须有"与真源逐字节比对"的断言（§5 第 6 条）；
   ② **同一份数据不要留第二份副本**——这条链上原本还有 `svg-paths.json`、`icons-data-32.ts`、
   `output/_work/*.json` 三个中间产物，它们丢了之后整条管线**根本无法重跑**。
   现在形状定义直达 `icons.ts`，没有中间文件可漂移。
10. **写进脚本的绝对路径"只在本机可用"**。`pixel-gen.mjs` 里曾写着
   `await import('file:///F:/<项目目录>/src/io/node-png.ts')`——换盘符/换机器直接崩，
   而在作者本机永远跑得通。跨模块引用一律用 `new URL('...', import.meta.url)`。
   同源的还有 CWD 相对路径：脚本里读 `'output/.../x.json'` 会让"从哪个目录调用"变成隐藏依赖。

## 7. 看着像 bug、其实是设计（别"修"）

1. `--lock-palette` 下色板已满且需要新颜色时**报错**而不是退化为近似色——拼豆用户买不到图纸外的颜色。
2. `countUsage()` / `getUsage()` **不含透明格**；透明格数另有 `countTransparent()`。
3. `render()` / `renderBlank()` 的算子**必须显式给 `color`**（无副作用路径不继承主色，才可复现）。
4. `render` 的 `ops` 在**第 4 个**参数，`renderBlank` 的 `ops` 在**第 1 个**。
   形状不同是历史原因，放错位置会**报错**（不会静默忽略）。
5. `trim` 在全透明或已无透明边时返回 `changed: false` 且不报错（批处理里这是合法状态）。
6. 抖动开启时 `cleanup` 被**强制关闭**——抖动的单像素点本身就是杂色。
7. 越界坐标静默裁剪；画布尺寸超 2048 夹紧到 2048，并在返回值里给出实际尺寸。
8. 拼豆内建色卡是**通用近似色**，不是任何品牌官方色号。
9. 单张素材失败不中断整批，但结尾以非零码退出（agent 需要"读失败清单 → 修素材 → 重跑"）。
10. `outline` 是**扩张**操作：对同一张图再描一次会向外再扩一圈。想加粗用 `offset`。
11. `--json` 时 stdout 只有 JSON，进度行默认静默（要看得加 `--progress`，它写 stderr）。
12. 侧栏折叠开关浮在**栏外**（画布区贴栏的那条边，三角形箭头指向收纳/展开方向），所以收起就是整栏隐藏、不留空窄边。**隐藏一栏必须同时把 grid 模板改成两列**：`display:none` 会把网格项从布局里摘掉、剩下两项自动重排，只改 display 会得到“画布宽度变成 0”。窄屏抽屉一次只开一个（浮层同时开两个会互相遮挡）；桌面两侧**独立**，可以都收起。
